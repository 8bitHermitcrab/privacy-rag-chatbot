# HMAC 키 무중단 교체 절차

키가 바뀌면 같은 개인정보도 토큰이 달라집니다. 그래서 가명 본문·토큰·임베딩·매핑·인물사전을 **새 키로 전부 다시 만든 뒤** 한 번에 넘어갑니다.
새 데이터는 기존 데이터와 섞이지 않도록 별도 스키마(`rag_v2`, `vault_v2` …)에 만들고, 서비스는 그동안 기존 버전으로 계속 돌아갑니다.

## 무엇이 버전별이고 무엇이 공용인가

| 구분 | 표 | 키 교체 때 |
| --- | --- | --- |
| 버전별 (키에 따라 바뀜) | `chunks`, `token_map`, `person`, `person_mention` | v1 = `rag`·`vault` 스키마, v2 = `rag_v2`·`vault_v2` 스키마에 새로 생성 |
| 공용 (하나만 유지) | `rag.document_info`(문서 권한), `auth.*`(계정·팀·정책·복원 기록·버전 등록부) | 그대로 두고 두 버전이 함께 사용 |

- 서버는 `.env`의 `DATA_VERSION`(기본 `v1`)과 `HMAC_KEY`를 함께 읽습니다.
- 서버는 시작할 때 `auth.data_version`에 등록된 키 지문과 `HMAC_KEY`가 맞는지 확인하고, 맞지 않으면 **시작하지 않습니다**.
- 키 지문은 키 자체가 아니라 HMAC(키, 고정 문구)의 앞 16자리라 지문으로 키를 알아낼 수 없습니다.

## 순서

1. **새 키 준비**: `.env`에 `NEW_HMAC_KEY=새 키`를 추가합니다. `HMAC_KEY`와 `DATA_VERSION`은 아직 바꾸지 않습니다.
2. **빈 v2 만들기**: `python -m starter.data_version create v2 --key-env NEW_HMAC_KEY`
   - 기본 표와 같은 구조(열·제약·인덱스·트리거·소유자·권한)로 `rag_v2`·`vault_v2`를 만들고, 등록부에 `BUILDING`으로 기록합니다.
3. **새 키로 적재**: `python -m starter.ingest --data-version v2 --key-env NEW_HMAC_KEY --reset`
   - 문서 권한 표에는 없는 문서만 '미확정'으로 추가하고, 기존 권한은 건드리지 않습니다.
4. **인물사전 만들기**: `python -m starter.person_dictionary --data-version v2 --key-env NEW_HMAC_KEY`로 미리 본 뒤, 같은 명령에 `--apply --plan <값>`을 붙여 반영합니다.
   - v2의 판정 캐시는 `person_dictionary_v2` 폴더에 따로 둡니다.
5. **준비 완료**: `python -m starter.data_version ready v2 --key-env NEW_HMAC_KEY`
   - 적재 건수, 문서 권한 연결, 새 키로 토큰이 다시 만들어지는지 확인한 뒤 `READY`로 바꿉니다.
6. **전환**: `.env`에서 `HMAC_KEY=새 키`, `DATA_VERSION=v2`로 **두 줄을 함께** 바꿉니다. `NEW_HMAC_KEY` 줄은 지웁니다.
   - 서버 관리자(9000)에서 챗봇 1 → 챗봇 2 순서로 재시작합니다. 재시작은 트래픽 제외, 처리 중 요청 대기, 재시작, 정상 확인, 복귀 순으로 자동 진행되므로 서비스가 끊기지 않습니다.
   - 처음 올라온 서버가 v2를 `ACTIVE`로 바꿉니다. 한 대씩 넘기는 몇 초 동안은 두 서버의 버전이 다를 수 있지만, 질문 하나는 한 서버 안에서 키와 데이터가 맞으므로 답변은 정상입니다.
7. **확인**: `python -m starter.data_version status`와 `/api/info`의 `data_version` 값을 확인하고, 실제로 질문해 봅니다.
8. **예전 버전 종료**: `python -m starter.data_version retire v1`
9. **예전 데이터 삭제(선택)**: `python -m starter.data_version drop v1 --yes`
   - **되돌릴 수 없습니다.** v1은 공용 문서 권한 표와 같은 스키마에 있어서, 표를 지우지 않고 데이터 표 4개만 비웁니다.
   - 복원 기록(`auth.restore_log`)에 남은 예전 토큰은 예전 매핑이 지워지면 원래 값을 찾을 수 없습니다. 감사 기간 동안은 삭제를 미루세요.

## 되돌리기

6번 이후 문제가 생기면 `.env`를 예전 값(`HMAC_KEY=예전 키`, `DATA_VERSION=v1`)으로 돌리고 다시 한 대씩 재시작합니다. 8번(retire) 전까지는 v1이 그대로 남아 있습니다.

## 서버가 시작되지 않을 때

| 메시지 | 원인 |
| --- | --- |
| HMAC_KEY 가 데이터 버전 … 을 만든 키와 다릅니다 | `.env`의 두 줄 중 하나만 바꿈 |
| … 은 아직 적재 중입니다 | 5번(ready)을 빠뜨림 |
| … 은 사용 종료된 버전입니다 | 이미 종료한 버전을 `DATA_VERSION`에 적음 |
