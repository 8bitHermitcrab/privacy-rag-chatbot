## 3. [실제] 지금 시스템이 하는 것

| 항목 | 지금 상태 |
|---|---|
| 설정할 수 있는 것 | 팀·직책마다 `can_restore`(실명 복원 허용) **켜짐/꺼짐 1개**뿐. 라벨별로 고를 수 없음 |
| 세 팀의 현재 설정 | 팀장 = 켜짐, 과장 = 꺼짐, 사원 = 꺼짐 |
| 실제 복원 동작 | **구현되어 있지 않음.** 설정이 켜져 있어도 모든 계정에 이름표(`<PERSON_…>`)만 보임 |

### 요청 정책과 시스템의 차이

| 직급 | [요청] | [실제] 설정만으로 표현할 수 있는 것 | 차이 |
|---|---|---|---|
| 팀장 | 7종 | 켜짐 = 7종 전부 (복원이 구현된다면) | 설정은 맞음, **복원 기능이 없음** |
| 과장 | 3종 (이름·전화·계좌) | 꺼짐 = 0종, 켜짐 = 7종 둘 중 하나뿐 | ❌ **"일부 라벨만"은 표현할 수 없음** |
| 사원 | 1종 (이름) | 꺼짐 = 0종 | ❌ 이름만 허용하는 설정이 없음 |

→ 요청 정책을 실제로 적용하려면 **"라벨별 허용" 설정 칸과 실명 복원 기능을 개발해야 합니다** (결과물 7의 개선 제안으로 넘김).

- 숫자는 문서 유형별 집계를 재배정안에 더한 값입니다. 6단계에서 실제로 반영한 뒤 다시 확인합니다.

## 5. 테스트 판정 기준

질문 답변(또는 근거 자료)에 라벨이 나왔을 때 이렇게 판정합니다.

| 상황 | 판정 |
|---|---|
| **허용** 라벨이 **실명**으로 보임 | 통과 |
| **허용** 라벨이 **이름표**로만 보임 | **미지원** (복원 기능 없음) |
| **차단** 라벨이 **이름표**로 보임 | 통과 (가려져 있으므로 정상) |
| **차단** 라벨이 **원문**으로 보임 | **실패** (예: 탐지 누락 문서) |
| 그 라벨이 들어 있는 문서가 팀에 없음 | 해당 없음 |
