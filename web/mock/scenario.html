어흥이 챗봇 · 권한별 시나리오

역할은 DB 설계(role_info)의 사원 · 팀장 · 관리자 세 가지 기준 · 가명처리 검수는 팀장이 자기 팀 문서만 담당한다고 가정

역할 검색 범위 실명 보기 가명처리 검수 계정 · 권한 관리 쓰는 화면
사원내 담당 문서불가 · 팀장에게 복원 요청불가불가① ②
팀장우리 팀 문서가능 · 사유 입력, 이력 기록우리 팀 문서 검수불가① ③ ④
관리자문서 검색 없음불가통계만 확인가능 · 사유 입력, 이력 기록① ⑤

시나리오 1 · 사원

"내가 맡은 고객 상담 기록을 찾고 싶어요"

  1. 로그인 → 첫 로그인이면 비밀번호 변경
  2. 어흥이에게 질문 → 내 담당 문서에서만 검색
  3. 답변 속 개인정보는 이름표(토큰)로 표시
  4. 실명이 꼭 필요하면 사유를 적어 팀장에게 복원 요청
  5. 요청 상태(대기 · 승인 · 반려) 알림 확인

시나리오 2 · 팀장

"팀원 요청을 처리하고, 가명처리가 맞는지 확인해요"

  1. 우리 팀 문서에서 검색 · 이름표 클릭 → 사유 입력 후 실명 보기
  2. 팀원 복원 요청 승인 또는 반려
  3. 검수 화면에서 탐지기가 애매해한 항목 확인
  4. 원문을 보고 개인정보 맞음 · 아님 · 범위 수정 판단
  5. 확정하면 문서를 다시 가명처리해 적재

시나리오 3 · 관리자

"계정과 권한을 관리하지만 문서는 보지 않아요"

  1. 새 직원 계정 만들기 (임시 비밀번호)
  2. 역할 · 팀 지정, 확인 대기 직원 정보 확정
  3. 역할 변경 · 계정 잠금은 사유 필수
  4. 모든 변경은 권한 변경 이력에 기록
  5. 검수 · 복원 통계만 보고 이상 징후 확인

관리자는 문서 내용과 실명을 보지 않음

실명 복원 · 권한 변경은 모두 사유와 이력이 남음

검수 결과는 탐지기 개선 데이터로 다시 쓰임

LLM에는 항상 가명처리된 텍스트만 전달
